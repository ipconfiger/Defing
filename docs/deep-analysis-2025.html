执行摘要

一个完成度高、工程纪律罕见的"毕业级"分布式配置中心原型，两轮安全审查 + 一轮全量修复后，对外安全承诺已基本闭环。

12 个 Rust crate、约 1.5 万行核心代码 + 3 千行三语言 SDK；契约三件套、确定性状态机、openraft 集群、内嵌 Admin UI、CI 全量流水线、混沌测试、SBOM 一应俱全。 设计文档（proposal → feasibility → design v1/v2/v3 → 15 份模块规格 → progress → code-review → deep-analysis）构成完整的需求-设计-实现-审查-修复证据链，远超同类项目平均水准。

V2 修复成果（F1–F20 与部署缺陷，除标注外全部落地并实测）

HTTP watch / branch_diff 泄漏 secret 密文（F1/F2） —— 已修复：统一掩码函数（dsh-core/wire.rs），实测 watch 事件无密文字段。
join / raft token 默认关闭（F3/S5） —— 已修复：集群模式强制 --join-token / --raft-token，无 token 启动即报错。
集群写响应 changes 恒空（F6） —— 已修复：R 升级为 WriteAck{version, events}，实测集群 publish 响应含 changes。
Dockerfile 缺 protoc / Go SDK ctx 失效 / UI 草稿数据破坏 —— 已修复：builder 补 protobuf-compiler；ctx 贯通（Watch 可取消）；UI 按类型渲染回读。
KEK 明文入 Raft 日志（F7） —— 已修复：kek_enc 自加密（实测日志 "kek":[]）+ redb 0600。
F4 / F5 / F8 / F9 / D-PRUNED / D-TYPE / F14 / D-DEL —— 全部落地（详见 §4 与 §7）。

残留风险（低危 / 设计取舍）

HTTP 数据面 /v1/* 无 token 鉴权（D2） —— secret 已不出网，非 secret 值依赖 TLS + 网络隔离。
Admin UI CSP 仍含 'unsafe-inline' —— 内联脚本外置需 UI 合批改造（P3）。
/metrics 无鉴权 · UI EventSource 不带 after_version · 契约测试断言弱 —— 低危信息泄露 / 断线丢事件 / ListMembers 零断言（D-TEST）。

亮点（同类对比下的优势）

单二进制交付

8.68MB，内嵌 Admin UI 与三语言 SDK，开箱即用

加密体系

AES-256-GCM 信封加密 + KEK 环轮换（含自加密日志载荷）

集群容错

Raft 强一致 + 混沌容错 + secret 全链路脱敏（现已无泄漏面）

§2

代码质量

分层架构、确定性状态机、错误处理、并发、复杂度、文档与测试的逐项评估。

分层架构 优

写路径统一收敛到 write_command；加密在 apply 之外执行（保证 Raft 重放确定性）；crate 依赖方向正确，无环。业务代码零 unsafe。

确定性状态机 优

D16 纪律彻底：apply 不读墙钟 / 不 IO / 不日志；时间戳命令载荷携带；会话判定只判 is_some()；轮换经 Raft 复制 + 幂等钩子，状态机零落库副作用。

2.5 复杂度（v2 变化）

  • dsh-api/src/lib.rs 单文件 3200+ 行过重（路由 / 鉴权 / 登录 / PA / 轮换 / 指标 / watch 全在一处）；
  • login / pa_login / rotate 的"LeaderRedirect → 转发"样板 v2 已收敛为 forward_request 统一 helper（含超时与 XFF 透传）；
  • 掩码实现 v2 已收敛为 dsh-core/wire.rs 单一出口（masked_value / mask_event_for_wire），消除初版"四套并存漏掩码"的温床（F1/F2 根因）；
  • dsh-core/src/state.rs 1889 行、单文件 5000+ 行的核心模块建议后续拆分。

2.8 评分小结（v2 修复后）

架构分层9.0
确定性设计9.5
错误处理7.0
并发6.0
复杂度6.5

功能闭环

配置生命周期、集群、watch、SDK、Admin UI、管理运维六个闭环的评估。

5.1 配置生命周期 完整

项目 → 分支 → 结构（不可变版本）→ 草稿 → 发布（幂等）→ 版本 → 回滚 → watch → 多格式渲染。v2 后集群/单机发布响应均携带 changes/affected。

5.2 集群闭环 完整

bootstrap/join（强制 token）/promote/remove-node（F14 校验）、leader 击杀容错、重启自动恢复、快照追赶、集群轮换（kek_enc 自加密）。chaos-test 实证。

5.3 watch 闭环 完整（v2）

SSE + gRPC 双通道、after_version 续传、慢消费者结束流（F5）、起点被裁剪 → snapshot_required（D-PRUNED）、重放类型保真（D-TYPE）。残留：重放 O(n) 快照 diff。

5.6 管理运维 完整

CLI admin 8 子命令、/healthz /readyz /metrics /audit、后台任务（版本裁剪/审计保留/DEK 重包）、备份。v2 新增 --trusted-proxy 旋钮。

5.4 SDK 闭环（v2 修复后）

v2 修复：Go gRPC ctx 贯通（Watch 可取消）；Go SSE 独立无超时 client（不再 5s 掐断）；TS 10s 超时 + import 失败回落 HTTP；Python gRPC watch 指数退避；三语言 watch 版本去重。

残留：三语言 getItem 仍拉全量（服务端 GetItem RPC 死代码）；HTTP 通道 version 参数静默丢弃；契约测试断言弱（get 不校验值、ListMembers 零断言、无断线续传自动化，D-TEST）。

5.5 Admin UI 闭环（v2 修复后）

v2 修复：草稿编辑器按类型渲染回读（int/float/json/array/bool 正确回显与保存，NaN 显式报错）、secret 留空不改、分支选择保持、401 跳登录。

残留：EventSource 不带 after_version（断线丢事件，低）；缺 reveal / 集群管理入口（功能面）。

5.7 功能闭环小结

9.0/10

核心业务闭环完整且经 e2e 实测；v2 修复后"集群变更明细缺失、watch 可靠性、SDK 工程缺陷、UI 数据破坏"四大断点全部消除。剩余扣分：契约测试断言强度（D-TEST）、UI 功能面缺口、GetItem 死代码。
